# 한국어 기술 산문 작성 표준

기술 블로그·보고서·발표문처럼 **한국어로 쓴 긴 산문**을 만들 때 따르는 규칙 모음이다.
사람이 읽는 **문서**와, 같은 규칙을 에이전트가 실행하는 **Claude Code 스킬 플러그인**으로 함께 제공한다.

다루는 범위는 네 층위다. 어조, 제목, 글의 구성, 그리고 생성형 모델이 쓴 글에서 나타나는 문체 흔적의 진단과 교정.
맞춤법·띄어쓰기 같은 어문 규범은 다루지 않는다. 그쪽은 국립국어원 어문 규정을 따르면 된다.

## 지도 — 지금 무엇을 봐야 하는가

이 표가 이 저장소의 목차다. 왼쪽에서 지금 상황을 찾고, 오른쪽 문서만 읽으면 된다.

| 지금 하려는 일 | 볼 것 | 한 줄 요약 |
|---|---|---|
| 글을 시작한다. 어떤 목소리로 쓸지 정해야 한다 | [docs/voice.md](docs/voice.md) | 어조 세 결과 그 선택 기준 |
| 제목·부제목을 짓거나 고친다 | [docs/title.md](docs/title.md) | 제목의 세 자리, 완결 명사구 원칙, 금지 유형 |
| 본문을 어떤 순서로 배치할지 모르겠다 | [docs/structure.md](docs/structure.md) | 설명 먼저 그림 나중, 섹션 구성, 편집자 노트 |
| 초고는 나왔는데 기계가 쓴 티가 난다 | [docs/ai-tells.md](docs/ai-tells.md) | 문체 흔적 11종의 정의·측정·교정 |
| 같은 뜻의 낱말 중 무엇을 쓸지 갈린다 | [docs/vocabulary.md](docs/vocabulary.md) | **작성 중.** 어휘 층위의 격 일치 규칙 |
| 화면에 올릴 때의 조판이 궁금하다 | [docs/typography.md](docs/typography.md) | 긴 한국어 본문의 줄간격·강조·글꼴 |

### 순서대로 한 편을 쓴다면

1. **어조를 고른다** — [voice.md](docs/voice.md). 글의 길이와 실리는 자리에 따라 세 결 중 하나를 정한다.
2. **쓴다** — 본문 배치는 [structure.md](docs/structure.md), 낱말 선택은 [vocabulary.md](docs/vocabulary.md).
3. **제목을 붙인다** — [title.md](docs/title.md). 본문이 끝난 뒤에 붙이는 편이 낫다. 제목이 먼저 정해지면 본문이 제목을 정당화하러 간다.
4. **게시 전 검수한다** — [ai-tells.md](docs/ai-tells.md). 11종을 채점하고, 점수가 아니라 증거 문구를 본다.

### 문서와 스킬은 어떤 관계인가

같은 규칙의 두 형태다. 문서는 사람이 읽고 판단하라고 쓴 것이고, 스킬은 에이전트가 절차로 실행하라고 쓴 것이다.
규칙이 어긋나면 **문서 쪽이 정본**이다. 스킬은 문서의 규칙을 실행 가능한 절차로 옮긴 것이므로, 문서를 고치면 스킬도 함께 고친다.

## 스킬 플러그인 설치

Claude Code에서 아래 두 줄을 실행하면 세 스킬이 들어온다.

```bash
claude plugin marketplace add pebblous/korean-tech-writing
```

```bash
claude plugin install korean-tech-writing@korean-tech-writing
```

Claude Code 안에서는 `/plugin marketplace add pebblous/korean-tech-writing` 으로도 같은 일을 할 수 있다.
설치 뒤 새 세션부터 세 스킬이 잡힌다. 지금 바로 쓰려면 `/reload-plugins`를 실행한다.

제대로 들어왔는지 확인한다.

```bash
claude plugin list
```

### 어디에 설치되는가

스킬 파일이 작업 중인 저장소 안으로 복사되는 것이 아니다. 실제 파일은
`~/.claude/plugins/` 아래에 받아지고, 설정 파일에는 어느 마켓플레이스를 알고 있고 어느 플러그인을
켰는지만 기록된다. `.claude/skills/`를 열어 봐도 아무것도 없는 것이 정상이다.

설치 범위는 세 가지 중에 고른다.

| 범위 | 지정 | 기록되는 곳 |
|---|---|---|
| user (기본값) | 생략 | 사용자 설정. 내 모든 저장소에서 쓴다 |
| project | `--scope project` | 저장소의 `.claude/settings.json`. 커밋해서 팀과 공유한다 |
| local | `--scope local` | 저장소의 로컬 설정. 나만 이 저장소에서 쓴다 |

**`project` 범위로 설치해 설정 파일을 커밋해도 팀원이 설치 단계를 건너뛰지는 못한다.**
그 파일은 이 저장소가 어느 플러그인을 쓰기로 했는지를 기록할 뿐이고, 실제 내려받기는
각자의 컴퓨터에서 일어난다. 팀원도 위의 두 줄을 그대로 실행해야 한다.
설정 파일을 커밋하는 값은 **무엇을 쓰기로 했는지가 저장소에 남는다**는 데 있다.

### 들어오는 세 스킬

| 스킬 | 하는 일 | 언제 부르나 |
|---|---|---|
| `ko-prose-humanizer` | 문체 흔적 11종을 채점하고 산문 질감만 교정 | 게시 전 마지막 검수 |
| `ko-voice` | 어조 세 결 중 하나를 골라 본문을 다시 씀 | 작성 단계, 또는 어조를 바꿀 때 |
| `ko-title` | 제목 세 자리를 점검하고 고쳐 씀 | 본문이 끝난 뒤 |

자세한 내용은 [plugin/README.md](plugin/README.md)에 있다.

## 아직 비어 있는 것

**어휘 층위**가 비어 있다. [docs/vocabulary.md](docs/vocabulary.md)에 자리만 잡혀 있고 내용은 작성 중이다.

이유를 밝혀 둔다. 어떤 한국어 기술 블로그 한 곳의 300여 편, 약 140만 자를 실측했더니 뜻이 겹치는 술어 계열에서
한자어를 고르는 비율이 26%에서 94%까지 널뛰었다. '따지다'와 '분석하다'가 섞이는 자리에서는 '분석하다'가 94%,
'재다'와 '측정하다'가 섞이는 자리에서는 '측정하다'가 82%인데, '바꾸다'와 '변환하다'가 섞이는 자리에서는
'변환하다'가 26%에 그쳤다. 한 글 안에서 어느 쪽을 쓸지 답할 근거가 없었다는 뜻이다.

방향은 정해 두었다. **판정 기준을 어원이 아니라 격 일치에 둔다.** '측정하다'와 '재다' 중 어느 하나가 틀린 것이
아니라, 한 문서 안에서 둘이 섞이는 것이 문제다. 규칙이 채워지면 이 자리에 들어온다.
