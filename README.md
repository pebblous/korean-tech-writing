# 한국어 기술 산문 작성 표준

생성형 모델이 쓴 한국어는 사실이 다 맞아도 읽으면 안다. 티가 난다.
그 티가 무엇인지 열한 가지로 추려 정의하고, 재는 법과 고치는 법을 정리했다.

이런 문장을

> 한 줄로 옮긴다 — 데이터는 더 이상 자산이 아니라 부채가 되어가고 있다는 점이다.
> 이 진단을 풀어 쓰자면, 문제는 세 가지 층위에서 동시에 발생하고 있다는 것이다.
> 수집의 층위, 정제의 층위, 검증의 층위 — 이 세 좌표가 하나의 평면을 이룬다.

이렇게 바꾸는 일이다.

> 데이터는 더 이상 자산이 아니라 부채가 되어가고 있다.
> 문제는 수집, 정제, 검증이라는 세 단계에서 동시에 벌어지고, 이 세 단계는 서로 맞물려 있다.

바뀐 건 문장의 결뿐이다. 수치도 표도 문단 순서도 건드리지 않는다.
위 예는 지어낸 것이 아니라 여기 실린 스킬을 실제로 돌려 나온 결과다.
전체는 [examples/](examples/)에 원문과 진단과 교정본이 그대로 있다.

맞춤법과 띄어쓰기는 다루지 않는다. 그쪽은 국립국어원 어문 규정을 보면 된다.

## 무엇을 볼지 고르기

문서 여섯 편이 있다. 지금 하려는 일에 해당하는 것 하나만 읽으면 된다.

| 지금 하려는 일 | 볼 것 |
|---|---|
| 글을 시작한다. 어떤 목소리로 쓸지 정해야 한다 | [voice.md](docs/voice.md) |
| 제목이나 부제목을 짓는다 | [title.md](docs/title.md) |
| 본문을 어떤 순서로 배치할지 모르겠다 | [structure.md](docs/structure.md) |
| 초고는 나왔는데 기계가 쓴 티가 난다 | [ai-tells.md](docs/ai-tells.md) |
| 같은 뜻의 낱말 중 무엇을 쓸지 갈린다 | [vocabulary.md](docs/vocabulary.md) (작성 중) |
| 화면에 올릴 때의 조판이 궁금하다 | [typography.md](docs/typography.md) |

한 편을 처음부터 끝까지 쓴다면 순서가 있다. 어조를 먼저 고르고, 쓰고, **제목은 맨 나중에** 붙이고,
게시 전에 진단한다. 제목을 먼저 정하면 본문이 제목을 정당화하러 간다.

## 스킬로 쓰기

같은 규칙을 Claude Code가 실행하는 형태로도 담았다. 두 줄이면 들어온다.

```bash
claude plugin marketplace add pebblous/korean-tech-writing
```

```bash
claude plugin install korean-tech-writing@korean-tech-writing
```

`ko-voice`가 어조를 고르고, `ko-prose-humanizer`가 게시 전에 진단하고 고치고,
`ko-title`이 제목을 본다. 설치했으면 그냥 "이 글 AI 티 나는데 좀 다듬어 줘"라고 말해도 잡힌다.

스킬 파일이 작업하던 저장소 안으로 복사되지는 않는다. `~/.claude/plugins/` 아래로 받아지고
설정 파일에는 무엇을 켰는지만 남으니, `.claude/skills/`를 열어 봐도 비어 있는 게 정상이다.
`--scope project`로 설치해 그 설정 파일을 커밋해도 팀원이 설치를 건너뛰지는 못한다.
받는 일은 각자의 컴퓨터에서 일어난다. 그 파일의 값은 **무엇을 쓰기로 했는지가 저장소에 남는** 데 있다.

자세한 건 [plugin/README.md](plugin/README.md)에 있다.

## 아직 못 채운 것

낱말을 고르는 기준이 비어 있다. 문장 구조는 열한 가지로 정리됐는데, '재다'와 '측정하다' 중
무엇을 쓸지 답하는 규칙은 아직 없다.

빈 채로 둔 이유는 [vocabulary.md](docs/vocabulary.md)에 적어 뒀다. 요지는 이렇다.
어느 한쪽이 틀린 게 아니라 **한 문서 안에서 둘이 섞이는 것**이 문제라서, 판정 기준을 어원이 아니라
격 일치에 두기로 했다. 규칙이 나오면 그 문서에 들어온다.
