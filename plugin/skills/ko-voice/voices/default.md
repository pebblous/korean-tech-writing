# default — 관찰자의 기술 산문

공통 일곱 원칙에 아래를 더한다.

## 정체

짧은 선언과 긴 사색이 교차하는 리듬. **날카롭되 따뜻하다.**

## 이 결만 더 강하게 갖는 것

| # | 원칙 | 적용 |
|---|---|---|
| 가 | **개인적 서사** | "나"가 있는 글. 직접 겪고 발견한 것. "처음 소스를 열었을 때" 같은 도입을 환영한다 |
| 나 | **겸손한 고백** | 한계와 편견과 놀라움을 솔직히 적는다. "이것이 믿기지 않았다" |
| 다 | **짧은 선언과 긴 사색의 교차** | "21개 파일. 5,526줄." 다음에 긴 관찰이 온다. 짧은 선언을 세 문장 연속 쓰지 않는다 |

## 전과 후

### 논문체 — 생성형 모델의 기본 출력

> 어떤 프레임워크(v1.2.12)는 21개 소스 파일, 5,526줄이라는 극단적으로 응축된 코드베이스 위에
> 컨테이너 격리 기반 다채널 에이전트를 구현한 오픈소스 프레임워크다.

### 평론가체 — 짧지만 차갑다

> 21개 파일. 5,526줄. 이것이 전부다.
> 플러그인 시스템? 없다. 설정 파일? 없다.

### default — 날카롭되 따뜻하다

> 21개 파일, 5,526줄. 처음 소스를 열었을 때, 이 안에 에이전트 하나의 전체 생애가 담겨 있다는
> 사실이 믿기지 않았다.
>
> 메시지를 받고, 생각하고, 답하는 그 순환의 모든 것이 여기에 있다. 파일 하나하나를 따라가 보면
> 설계자가 내린 수십 번의 선택이 보인다. 어떤 선택은 우아하고, 어떤 선택은 대가를 치른다.
> 이 글은 그 선택들을 하나씩 열어보는 과정이다.

### default — 한계를 말할 때

> 작게 만든 것에는 이유가 있지만, 대가도 있다.
>
> 여기에는 벡터 검색이 없다. 반성적 메모리도 없다. 오래 대화하면 문맥 창이 바닥난다.
> 메모리 구조를 다룬 서베이가 제안하는 쓰기·관리·읽기 순환을 떠올려 보면,
> 이 프레임워크는 아직 기억하는 법을 배우지 못한 셈이다.

## 변환 규칙

| 전 | 후 |
|---|---|
| "본 보고서에서는 ~을 규명한다" | "이 글은 ~을 열어본다", "이 글은 ~을 따라간다" |
| "본 보고서" | "이 글" (각주의 자기 참조는 그대로 둔다) |
| "혁신적", "획기적" | 사실만. "27,690개의 별이 말해 준다" |
| "~되었다", "~된 것이다" (수동) | "~했다", "~이다" (능동) |
| 무인칭 서술 | 일인칭 관찰자. "열어 보면", "따라가 보면", "처음 봤을 때" |
| "X? 없다. Y? 없다." 연속 | "X가 없다. 이것은 의도된 선택이다." (맥락을 준다) |
| "~다 — ~다" 동격 재진술 | 마침표로 닫고 다음 문장을 시작한다 |
| "한 줄로 옮긴다 —" | 인용을 바로 시작한다 |

## 자기 점검

```bash
# 일인칭의 흔적이 한 번 이상 있어야 한다
grep -cE "처음|믿기지 않|따라가 보면|열어 보면|돌아보면|새삼" "$FILE"
```

짧은 문장이 세 개 이상 연속되는지는 자동으로 잡기 어렵다. 소리 내어 읽어 확인한다.

## 분량

제한 없음. 대상 글의 분량에 맞춘다.

## 자사 연결

본문 흐름 중 자연스러운 자리에서 한두 문장. 광고처럼 떨어져 나오지 않게 한다.
보통 결론 단락이나 한계를 논한 직후가 자연스럽다.

본문 결론이 "그러므로 우리 제품"으로 건너뛰면 안 된다. 그 경우 편집자 노트로 분리한다.
