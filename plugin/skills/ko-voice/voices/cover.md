# cover — 잡지 표지글

공통 일곱 원칙에 아래를 더한다.

## 정체

긴 글을 소개하는 **표지글**이다. 사실을 나열하는 것이 아니라 맥락이 이어지는 짧은 글이다.
짧고 단정하고 약간 도발적이다. 스크롤을 멈추게 만드는 첫 문장에서 시작해 흐름을 타고
담대한 한 줄로 닫는다.

## 다른 두 결과의 차이

| 항목 | default | reflective | cover |
|---|---|---|---|
| 분량 | 제한 없음 | 1,500~2,500자 | 3~5문단, 각 3~5줄 |
| 일인칭 | "나"가 강함 | "저는 ~봅니다" 절제 | 거의 없음 (관찰자) |
| 호흡 | 짧은 선언과 긴 사색의 교차 | 긴 호흡, 중간에 멈춤 | 짧고 빠른 호흡 |
| 첫 문장 | 구체적 관찰 | 조용하지만 오래 남는 통찰 | **의외의 사실** |
| 마무리 | 단정 | 방향 제시 | 담대한 한 줄과 링크 |

## 얼개 — 네 단계

1. **의외의 사실로 연다.** 독자의 예상을 깨는 사실이나 질문. 설명하지 않는다.
2. **맥락을 잇는 질문.** "왜 지금일까", "이것이 왜 중요한가."
3. **흐름 문장.** 네 가지를 목록으로 나열하지 말고 하나의 흐름으로 잇는다.
4. **담대한 마무리.** 숫자를 근거로 한 문장.

## 나쁜 예 — 사실 나열

```
어떤 프로젝트가 코드 저장소 인기 순위 1위를 기록했다.
하루 1,962개, 누적 13,535개의 별. 경쟁 프로젝트(11,844개)를 추월한 것이다.

단순한 유행이 아니다. 새 릴리스, 표준 단체 합류, 재단 가입이
6개월간 연쇄적으로 일어난 구조적 흐름의 결과다.

핵심 구조는 명확하다.
- 첫째 계층: 84개 이상의 연결기로 신뢰 계층 구축
- 둘째 계층: 이중 관측 기반 운영 체계
- 셋째 계층: 정밀 진단
- 넷째 계층: 합성 데이터 생성
```

**문제**: 사실이 맥락 없이 나열된다. 독자가 "왜 이걸 읽어야 하지"를 못 느낀다.
그리고 마지막 목록은 그냥 제품 소개다.

## 좋은 예 — cover

```
코드 저장소 인기 순위 1위를 찍은 프로젝트가 화려한 도구도, 새 프레임워크도 아니었다.
메타데이터 카탈로그였다.

하루 1,962개. 누적 13,535개의 별.
대기업이 만든 경쟁 프로젝트를 조용히 추월했다.

왜 지금일까. 6개월 사이에 벌어진 일을 보면 답이 보인다.
새 개발 도구가 실렸고, 표준 단체에 합류했고, 재단에 들어갔다.
하나하나는 기술적 이정표에 불과하다. 그런데 이것이 연쇄적으로 터지면서
하나의 이야기가 만들어졌다. 메타데이터 카탈로그가 인공지능 에이전트의
의미 계층이 된다는 것.

(우리가 이 지점을 보는 이유 한두 문장. 제품 나열이 아니라 관심의 이유로.)

다음 승부처는 모델이 아니라 데이터 기반 시설이다.

[링크]
```

핵심은 네 단계다. 의외의 사실, "왜 지금일까", 흐름 문장, 담대한 마무리.

## 문장 규칙

- **한 문장에 하나의 생각.** 길어지면 자른다.
- **줄바꿈을 아끼지 않는다.** 화면에서 읽히는 글이라 시각적 호흡이 필요하다.
- **목록 대신 흐름.** 네 항목을 불릿으로 늘어놓지 말고 한 문장으로 잇는다.

## 어미

| 용도 | 어미 |
|---|---|
| 선언 | ~입니다, ~합니다, ~이다 |
| 부드러운 전환 | ~이죠 (절제한다. 문단당 한 번까지) |
| 강조 | ~것입니다, ~할 수 있습니다 |

## 이모지

- 표제에 하나까지 허용한다
- 목록 기호 대신 쓰는 것은 허용한다
- 문장 중간에 넣지 않는다
- 세 개 이상 연속은 금지한다

## 비유는 한 편에 하나

조직마다 비유 체계를 하나 정해 두고 모든 짧은 글에서 같은 것을 쓰는 편이 낫다.
읽는 사람이 반복을 통해 그 조직의 관점을 익히기 때문이다.

개념 하나에 비유 하나를 고정하고 그 밖의 비유는 쓰지 않는다.
비유를 정하지 않으면 글마다 다른 비유가 나오고 결국 아무 인상도 남지 않는다.

## 플랫폼별 조정

| 플랫폼 | 조정 |
|---|---|
| 전문가 대상 | 업계 맥락(규제, 흐름)을 언급한다. 해시태그 서넛 |
| 짧은 형식 | 핵심만 압축한다. 링크는 마지막에. 해시태그 한둘 |
| 긴 형식 허용 | 이야기를 확장할 수 있다. 질문으로 닫아 참여를 유도한다 |

## 자기 점검

- [ ] 첫 문장이 의외의 사실인가. 사실 나열로 시작하지 않았는가
- [ ] 사실 덩어리 사이에 맥락을 잇는 질문이 있는가
- [ ] 목록 대신 흐름 문장으로 이었는가
- [ ] 마무리가 담대한 주장인가. 숫자를 근거로 한 문장인가
- [ ] 이모지가 문장 중간에 들어가 있지 않은가
- [ ] 자사 언급이 제품 나열이 아니라 관심의 이유로 쓰였는가

## 짧은 글의 더 좁은 임계값

같은 신호라도 짧은 글에서 더 두드러진다. `ko-prose-humanizer`를 부를 때 아래를 적용한다.

| 흔적 | 짧은 글 임계값 |
|---|---|
| 줄표 | 600자당 1개 이하. 가장 짧은 형식은 0 |
| 메타 예고문 | 0 필수 |
| 수치 과적재 | 한 단락 3개, 가장 짧은 형식은 2개 |
| 세 마디 병렬 | 한 편에 한 번만 |
| 자사 점프 | 단정형 홍보 어휘 0건 |

## 분량

3문단에서 5문단, 각 3줄에서 5줄. 피드에서 잘리지 않는 길이다.

## 영어로 쓸 때

직역하지 않는다. 영어권 잡지의 톤으로 다시 쓴다.
"~이다"를 그대로 옮기지 말고, 의외의 사실로 여는 첫 문장부터 영어로 새로 짠다.
